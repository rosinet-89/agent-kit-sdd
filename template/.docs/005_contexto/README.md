# Índice de contexto del proyecto

Documentos que responden una pregunta del proyecto (negocio, estructura, procesos, integraciones) y
se leen **bajo demanda**: solo cuando la petición toca lo que describen. Un archivo
`<prefijo>_<Nombre>.md` por documento. Este índice es el resumen: búscalo antes de leer o de
preguntar algo que un documento ya responde.

## Cómo usarlo

1. Busca aquí el tema de la petición y lee solo el documento cuya columna «Cuándo leerlo» encaje.
2. Un documento abre con «Objetivo» (qué pregunta responde) y «Última verificación» (fecha y con qué
   se contrastó). Un documento viejo se lee como pista, no como verdad: contrástalo con el código.
3. Al cerrar un requerimiento que tocó lo que describe un documento, `/sdd-cierre` propone
   actualizarlo y su fecha; no se escribe sin visto bueno.
4. Si el índice y el documento discrepan, manda el documento: corrige el índice.

## Guía

- Numeración y ancho del prefijo: `.docs/002_specs/README.md` › «Numeración única».
- Los tipos de documento son una guía abierta, no una lista cerrada: negocio, estructura, procesos,
  integraciones u otros que el proyecto necesite. No se atan a un lenguaje ni a una herramienta.
- Las reglas genéricas de un framework no van aquí: van a una skill de dominio en `.agents/skills/`.
- Lo histórico va a `.docs/legacy/`, fuera de este índice.
